PHOTO360 — CLOUD.RU FIX 1

ПРИЧИНА ПАДЕНИЯ СТАРОЙ РЕВИЗИИ
Команда npm start автоматически запускала prestart. Скрипт сборки пытался
перезаписать /app/index.html и dist уже внутри работающего контейнера, где
пользователь node не имел прав на запись. Результат: EACCES и цикл перезапусков.

ЧТО ИСПРАВЛЕНО
1. Релиз собирается один раз во время docker build.
2. Контейнер запускается напрямую командой node server.js и не вызывает prestart.
3. Изменяемые служебные данные хранятся в /tmp/photo360-dashboard.
4. Контейнер по-прежнему работает без привилегированного режима и не от root.

СБОРКА И ПУБЛИКАЦИЯ
Из каталога проекта выполните ту же команду docker buildx build, которой был
опубликован первый образ, но замените тег latest на cloudru-fix1. Платформу
оставьте linux/amd64.

После публикации образа в Cloud.ru:
1. Оставьте старую ревизию остановленной.
2. Создайте новую ревизию на основе старой.
3. В новой ревизии выберите образ с тегом cloudru-fix1.
4. Команды и аргументы оставьте пустыми.
5. Порт оставьте 8080, привилегированный режим — выключенным.
6. Переменные, секреты, масштабирование и дополнительные опции не меняйте.
7. После запуска сначала откройте /health, затем сам дашборд.
