ФОТОМОНИТОРИНГ ОБЪЕКТОВ — ВЕРСИЯ 2.0.7 FAST LOAD RC5

ГЛАВНЫЕ ИЗМЕНЕНИЯ
Стартовый index.html сохранён лёгким: 21 702 байта против 83 735 байт в RC3. Тяжёлые стили,
конфигурация и загрузчик вынесены в отдельные файлы с хешами содержимого.
Это повторяет транспортную схему рабочей старой версии sc-photo360 и устраняет
тайм-аут UserGate на монолитном HTML, сохраняя логику и защиту версии 2.0.7.

RC5 ускоряет этапы после открытия страницы:
- config и bootstrap скачиваются параллельно и используют immutable-кэш;
- основные скрипты заранее загружаются, пока пользователь вводит пароль;
- успешный вход не ждёт фоновой очистки серверного счётчика ошибок;
- API Яндекс Карт загружается параллельно с данными после успешного входа;
- фотографии проходят через защищённый серверный и браузерный кэш;
- фото начинает прогреваться при наведении или нажатии на маркер объекта.

ЦЕПОЧКА ЗАГРУЗКИ
1. Браузер получает лёгкий HTML и статический экран входа.
2. Минимальный загрузчик получает конфигурацию и основной bootstrap параллельно,
   с двумя попытками и отдельными тайм-аутами.
3. Пароль проверяется Netlify Function с тайм-аутом и повтором запроса.
4. После входа запрашивается быстрый серверный кэш либо защищённая резервная
   копия данных. Nextcloud не блокирует первый экран дашборда.
5. Локальные компоненты загружаются с уникальными именами версии. При временном
   сетевом сбое запрос повторяется автоматически.
6. API Яндекс Карт уже загружается параллельно, но сама карта создаётся только
   после карточек, показателей и фильтров.
7. Затем фоном проверяется актуальный Excel; при новой версии страница безопасно
   обновляется.
8. Ошибка Яндекс Карт не скрывает дашборд.

ЗАЩИТА И КЭШ
- Production публикует только папку dist с одиннадцатью безопасными файлами.
- dashboard_data.xlsx, локальная резервная копия и исходники не публикуются.
- Резервные данные выдаются только защищённой Netlify Function после входа.
- JS/CSS-файлы имеют имена с хешем содержимого *.v207.<hash>.*. Поэтому браузер и
  корпоративный прокси не могут смешать 2.0.6 и 2.0.7.
- Обычная пользовательская сессия хранится в HttpOnly/Secure cookie 12 часов.
- SameSite=Lax выбран для совместимости с мобильными WebView и внешними ссылками.

СОХРАНЕНО И УСИЛЕНО
- двусторонняя запись статусов в Excel на Nextcloud;
- operationId, автоматический повтор pending и отдельный конфликт ETag;
- 30 версионных резервных копий перед записью;
- администраторский режим;
- автоматический период по средам в 23:30 МСК;
- скрытые в интерфейсе координаты;
- фотографии из Nextcloud с понятным состоянием ошибки.
- защищённый кэш фотографий Netlify Blobs и приватный кэш браузера на сутки;
- прямое Nextcloud-превью и download URL сохранены как резерв.

ПЕРЕМЕННЫЕ NETLIFY
Существующие переменные не удаляйте и не меняйте. Обязательны:
  DASHBOARD_ACCESS_PASSWORD
  DASHBOARD_ACCESS_TOKEN_SECRET
  DASHBOARD_ADMIN_PASSWORD
  DASHBOARD_ADMIN_TOKEN_SECRET
  YANDEX_MAPS_API_KEY

Также сохраняются ранее настроенные переменные Nextcloud и администраторского
режима. Полный список находится в ADMIN_SETUP_NETLIFY.txt.

Новые переменные для фотографий необязательны: текущая папка и версия уже
встроены. При переносе фото можно задать NEXTCLOUD_PHOTO_PUBLIC_FOLDER_URL и
NEXTCLOUD_PHOTO_VERSION, одновременно обновив значения в config.source.js.

ДЕПЛОЙ
1. Распакуйте архив в отдельную папку.
2. BAT-файлы ключа и пароля не нужны.
3. Загрузите всю папку новым Production deploy в Netlify.
4. Netlify сам выполнит npm run build и опубликует только dist.
5. После deploy проверьте обычное окно, инкогнито, телефон и рабочую сеть.

ЛОКАЛЬНЫЙ ПРЕДПРОСМОТР
Запустите PREVIEW_LOCAL.bat. Локально используется data.v207.js, сформированный
из dashboard_data.xlsx. Серверная авторизация, запись и ключ Netlify локально
не работают; интерфейс и данные остаются доступны для проверки.

РЕАЛЬНОЕ ОГРАНИЧЕНИЕ
Если сеть полностью блокирует домен testp360.netlify.app на уровне DNS или
межсетевого экрана, код сайта физически не сможет прийти на устройство. Для
такого случая нужен отдельный разрешённый домен или зеркало. Все частичные
сбои, тайм-ауты и блокировки Nextcloud/Яндекс Карт версия 2.0.7 переживает без
чёрного экрана.

Первая загрузка конкретной фотографии после deploy всё ещё зависит от скорости
Nextcloud. После первого успешного запроса копия сохраняется на сервере и в
браузере; следующие открытия этой фотографии должны быть заметно быстрее.

UPDATE_SOURCE_EXCEL.bat либо подтвердите актуальность серверного кэша.
